## 1. `kicad-sch-codegen/`

**适用范围**：需要出电路原理图，但本机没有 KiCad / 嘉立创EDA 客户端；或需要**可脚本重复生成、可机器校验**的原理图交付链。涵盖小型模拟电路（分压/运放级/滤波）到多引脚 IC。

**使用方法**：按产物选路线 —— ①要好看的 PNG 用 `schemdraw`；②多引脚 IC 或要查悬空引脚用自带 `reference/` 的手搓 DSL + `audit()`；③要交付嘉立创用 KiCad v5 工程 zip。

**依赖**：Python + matplotlib（出 PNG 零新增依赖）；`schemdraw` 可选。

**已验证的效果**：实际交付了一套双通道模拟前端原理图工程，ERC 0 错 0 警，BOM 25 项 55 件。
`audit()` 首次运行即抓出"符号画在 `yc±hh`、导线却接在别的 y 上"的引脚脱接错误（差 6 单位，肉眼不可见）。

**失效条件 / 边界**：
- 自动校验**只能验"实现与意图一致"**，验不了"意图本身对不对" —— 交付前仍须拿设计文档逐条核对
- `reference/` 中标"项目专用"的脚本，元件表与坐标写死，**当模板读，别当通用工具跑**
- 多引脚 IC 用 `schemdraw` 的 `elm.Ic()` 会静默叠字出废图，必须人眼复核

## 2. `llm-hw-debug-pitfalls/`

**适用范围**：用大模型做硬件/模拟电路调试时。典型触发场景：
模型给出**自信的机理解释**但你怀疑结论；自检工具（ERC/DRC/lint/`audit()`/单元测试）**显示通过**但设计本身可能就有错；反复排查同一现象、每个假设都被推翻。

**使用方法**：三条判据 ——
①看到"异常"先用基本方程算理论值；
②自检通过的假阳性，根因是**检查器与被检查者共享了同一错误假设**；
③每个排除步骤必须有可判定的判据，"不可复现"是合法结论。
配第六节的自查表使用。

**依赖**：无（纯方法论）。

**已验证的效果**：一次完整排查中模型连错 **6 次**，全部由实测数据纠正，其中 2 次是在**错误前提下做的正确推理**。
最终两通道调通、相位差 0°、量程利用率 66~78%。同一项目中该模式第二次命中：
ERC 报 0 错 0 警，但钳位二极管实际接错了位置，只有独立的数值仿真才发现。

**失效条件**：
- 纯数字逻辑的综合/时序问题 → 改用仿真与时序报告
- 无法实测（没有示波器/万用表）→ 强行使用会退化成空推理
- 需求本身不明确 → 那是需求问题，不是调试问题

## 3. `pcb-sch-cross-audit/`

**适用范围**：手上有一个 PCB（`.kicad_pcb` 或 zip）和一份原理图，要回答三个问题——
"这块板有没有问题？""能不能和电路图对上？""有人改过哪些元件？"。
适用于**任何用 KiCad 格式交付 PCB 的工程**（自己生成或他人交付都行）；典型时机是导入 EDA / 送去打样之前。
**不适用**：布线质量评审、SI/EMC 仿真、机械干涉。

**使用方法**（`reference/audit_pcb.py` 路径已参数化，换项目不用改代码）：

```bash
python audit_pcb.py --pcb <xxx.kicad_pcb> \
                    --sch <xxx.sch> --lib <xxx-cache.lib> \
                    --gen <gen_pcb.py>        # 可选：读其摆放表以识别手改
                    --board-w 100 --board-h 60 --out pcb_audit_raw.txt
```

做**四方比对，四项均为自动检查**：①原理图 ↔ PCB 逐焊盘网络；②PCB 生成器意图 ↔ PCB（识别手改）；
③引脚数 ↔ 焊盘数；④**value/丝印文本 ↔ 焊盘网络**（工具输出段【2b】，专抓"丝印标错"）。
另附几何/间距/丝印压盘/占位封装等可制造性检查。

> 三个防呆设计：输入文件不存在 → **报错退出**（参数默认值指向示例项目，静默跑通会拿错板当依据）；
> 默认输出**带时间戳**不覆盖历史；覆盖时打印告警。

**依赖**：Python 3 标准库（`re / os / time / collections / argparse`），无第三方包。

**⚠ 多副本同步（本目录最容易踩的坑）**：本技能有**两份文件**（`SKILL.md` + `reference/audit_pcb.py`），
分发在仓库 `skill/`、项目 `tools/`、`~/.claude/skills/`、`~/.workbuddy/skills/` 等处。
**改一处必须同步其余全部**并核对 —— 注意**两个文件都要核**：本技能已因"只核 `.py`、漏了 `.md`"
而真实漂移过一次（防漂移措施自己漂移）。唯一允许的差异：`~/.workbuddy/…/SKILL.md` 的 frontmatter
多一行 `agent_created: true`（WorkBuddy 标记"模型自建技能"；Claude Code 不用该字段）。
同步后用 `md5sum` 核对 `.py`，用"剥掉该行后 `diff`"核对 `.md`。

**已验证的效果**：一次双通道模拟前端的 PCB 交付审计（49 封装 / 101 焊盘 / 21 网络）——
网络表逐焊盘 **0 差异**、查出 1 处**文字与网络互换**（板上写 `V_VB`、焊盘实际在 `V_OUT` 网上，
这种错**网络表比对照样全绿**，只有第 ④ 项能抓到；若漏检，调试时会按丝印探到错误节点）、
查出 1 处占位封装需换真件。**第 ④ 项的回归验证**：缺陷版报 ⚠4 处、修复版 ✓0 处。
工具自身也从 6 处**假差异**收敛到 0：原因是网络重建漏了"导线端点落在另一条导线中段（T 型搭接）"
与"网络标签点也要并入"两条规则。

**失效条件 / 边界**：
- 只验"PCB 与原理图一致"，**两者同错时照样通过** —— 与 `kicad-sch-codegen/` 的边界同类，须另拿设计文档核对意图
- 需要原理图**源文件**；只有 Gerber / 截图时退化为人工比对
- 第 ② 项依赖"生成器脚本存在且其表就是意图"；PCB 若纯手工绘制，该项会把所有手工改动都列出来（此时当作"手工改动清单"人工判性质）
- 第 ④ 项只能校验**文字本身就是网络名**的标注；自由描述型丝印（如 `CT in`）仍需人眼过一遍
- 第 ④ 项按几何就近归属板级丝印（阈值 8mm），排布极密时会保守跳过（宁漏报不误报）

## 提炼方法说明

两项技能均由「失败与观察 → 归纳 → 用新场景验证」的流程产出：

1. **记录原始轨迹**（提示词 → 模型回答 → 实测反馈 → 纠错），见仓库 `docs/worklog/`
2. **归因**：区分"模型不懂"与"前提错误"两类失败
3. **抽象**：把一次性经验写成对陌生题目也成立的判据，并写明**失效条件**
4. **验证**：在新场景中检验判据是否仍然成立

> 赛题 3.3.5.2 要求每一项技能"写明适用场景、使用方法与已验证的效果，
> 并说明是从哪些失败或观察中总结得出" —— 上文各节即对应此要求。
