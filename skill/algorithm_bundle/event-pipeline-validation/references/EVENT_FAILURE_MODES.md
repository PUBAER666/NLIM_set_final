# 事件管线常见失败模式

## 1. 尖峰即事件

**现象**  
单个尖峰触发分类。

**风险**  
噪声、开关抖动、瞬态被当成设备状态变化。

**改进**  
增加前后稳定状态与多时间尺度持续性检查。

## 2. 一次开关被检测多次

**现象**  
短时间内连续出现多个候选。

**改进**  
使用 duplicate/NMS window，并保留更强证据。

## 3. 微小漂移被当作主要事件

**现象**  
ΔP、ΔI 很小，但 z-score 因噪声很低而很高。

**改进**  
z-score 之外增加绝对物理量下限。

## 4. Leading glitch

**现象**  
主事件前出现弱的短促变化。

**改进**  
把短时间 A -> B -> C 作为 episode 分析。

## 5. Overshoot / rollback

**现象**  
启动先过冲，随后回落到稳定状态。

**改进**  
比较最终 A -> C 净变化，不只看单个内部 transition。

## 6. 分类器反向选择 residual

**现象**  
从多个 residual 中挑“分类结果最好看”的那条。

**风险**  
引入标签/模型偏置，离线结果虚高。

**改进**  
residual 选择只使用物理/信号规则。

## 7. Ground Truth 参与决策

**现象**  
用 GT 修正候选事件后再汇报指标。

**风险**  
评估失真。

**改进**  
GT 只能在最终决策生成之后做匹配和统计。
