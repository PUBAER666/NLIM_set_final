# PCB ↔ 原理图 只读交叉审计

## 何时用

- 拿到一个 PCB（`.kicad_pcb` / 嘉立创导出 / zip），要判断它**和手上的原理图是否一致**
- 有人（人或模型）在 PCB 里改过东西，需要**查出改了哪些**
- 板子还没布线，但要在导入 EDA 之前把"网络错接 / 缺件 / 封装不对 / 丝印标错"先筛一遍
- 作为"改完怎么验证"的一环：每次重生成 PCB 后跑一次，证明改动没破坏对应性

**不适用**：布线质量评审（需要走线才能评）、SI/EMC 仿真、机械结构干涉（那是 3D 软件的事）。

---

## 一、四方比对（少一方就会漏或误判）

| # | 比对 | 能查出 |
|---|---|---|
| 1 | 原理图（`.sch` + `-cache.lib`）↔ PCB | 网络错接、缺件、多件、封装字段不符 |
| 2 | **PCB 生成器意图表 ↔ PCB** | 人手改动：封装被换、元件被挪、增删（前提：工程有脚本生成器） |
| 3 | **引脚数 ↔ 焊盘数** | 封装不匹配（3 脚器件套了 2 脚封装之类） |
| 4 | **value / 丝印文本 ↔ 焊盘网络** | 丝印标错（最危险、最隐蔽：丝印说有 X，实际探到 Y） |

> 第 2 项是"查出改动"的关键：**先分清哪些差异是生成器写的、哪些是人改的**，
> 否则会把生成器的书写习惯（如空格→下划线、`10k 3296W`→`10k`）误报成"用户改动"。
> 第 4 项必须单独做，因为**网络表比对是查不出丝印标错的**——焊盘网络完全正确，只有丝印是错的。

**四项都已实现为自动检查**（不是靠人眼看输出）：

| 项 | 工具输出段落 |
|---|---|
| 1 | 【3】网络表比对 + 【9】F2 封装 ↔ 实际封装 |
| 2 | 【5】与生成器意图比对 |
| 3 | 【9】引脚数 ↔ 焊盘数 |
| 4 | **【2b】丝印 / value 文本 ↔ 焊盘网络** |

## 二、网络重建的三条铁律（漏一条必然误报）

独立解析原理图重建网络表时，并查集必须合并：

1. 导线两端；
2. **导线端点落在另一条导线中段（T 型搭接）必须合并** —— 最常漏，原理图里大量用"贴到线段中间"的接法；
3. **引脚 / 电源符号 / 网络标签**三类点都要并到导线上。

> **实测教训**：只并"引脚 + 电源符号"、漏掉**网络标签点**时，标签落不到网上 →
> 出现 6 个引脚"假孤立"，网络总数 20→26，报告里凭空多出 6 处"PCB 未接"的假差异。
> 补齐后 0 差异。**误报比漏报更浪费人**：它会让你去改一个本来正确的板子。

## 三、几何 / 可制造性清单（未布线板也能查）

- 板框闭合性：Edge.Cuts 每条边的端点须被**两条边**共享（悬空端点 = 板框有缺口）
- 元件 courtyard 包围盒两两重叠 / 越出板框 / 距板边 <2.5mm / 压安装孔禁布区
- 焊盘间距 DRC-lite（**不同网络**、阈值 0.20mm）、焊盘环宽 <0.15mm、丝印文字压焊盘
- 走线 / 过孔 / 铺铜计数：**0 走线要明确说明这是"底板"性质**，导入后必须自己布线
- 占位封装识别：lib 名含 `GENERIC` / `NEEDS_VERIFY` / `REPLACE` → 必须换真封装，
  并提醒**真实器件脚数可能更多**（例：3 脚的占位 3.5mm 耳机座，真品 PJ-320A 多为 5 脚带开关，
  多出的开关脚要显式处理，否则转 PCB 报未连接）

## 四、工具用法

`reference/audit_pcb.py` 即本项目使用的实现（路径已参数化，换项目不用改代码）：

```bash
python audit_pcb.py \
  --pcb  <xxx.kicad_pcb> \
  --sch  <xxx.sch>  --lib <xxx-cache.lib> \
  --gen  <gen_pcb.py>        # 可选：读其 PLACE 表以识别手改；不存在则跳过第 2 项比对
  --board-w 100 --board-h 60 \
  --out  pcb_audit_raw.txt   # 可选；默认 pcb_audit_raw_<时间戳>.txt
```

输出 12 个段落：`【0】`规模 / `【1】`位号 / `【2】`数值 / **`【2b】`文本↔网络（第 ④ 项）** /
`【3】`网络表逐焊盘 / `【4】`焊盘级归属 / `【5】`生成器意图 / `【6】`几何 / `【7】`布线状态 /
`【8】`封装核对 / `【9】`F2封装 / `【10】`焊盘间距 DRC-lite。

**依赖**：Python 3（只用标准库：`re / os / time / collections / argparse`），无第三方包。

### 4.1 三个刻意的"防呆"行为

| 行为 | 为什么 |
|---|---|
| **输入文件不存在 → 报错退出（exit 2）** | 参数默认值指向示例项目。若换项目忘传参却"静默跑通"，会拿**别的板**当依据，得出彻底的错结论。宁可失败 |
| **默认输出带时间戳** `pcb_audit_raw_<yyyymmdd_HHMMSS>.txt` | 审计要留历史。想去固定名就显式传 `--out` |
| **覆盖已有文件时打印告警**；`--out` 的上级目录不存在会自动建 | 避免悄悄抹掉上一次的证据 |

### 4.2 ⚠ 多副本同步（本技能最容易踩的坑）

本技能有**两份文件**（`SKILL.md` + `reference/audit_pcb.py`）分发在**多个位置**：

| 位置 | 放什么 | 用途 |
|---|---|---|
| 仓库 `skill/pcb-sch-cross-audit/` | **两份** | **唯一真源**，竞赛提交物 |
| `hardware/afe_v0/tools/audit_pcb.py` | 只有 `.py` | 本项目入口 |
| `~/.claude/skills/pcb-sch-cross-audit/` | **两份** | Claude Code 自动加载 |
| `~/.workbuddy/skills/pcb-sch-cross-audit/` | **两份** | WorkBuddy 自动加载 |

> **改任何一处，务必同步其余全部**，并核对 —— 否则会出现"文档说已修、实际跑的还是旧版"，
> 进而**误判为已通过**。
> **本技能自己就栽在这一点上**：第一版同步说明**只覆盖了 `.py`，漏了 `SKILL.md`**，
> 结果 `.md` 悄悄漂移了（WorkBuddy 那份多一行、措辞也不同）—— 防漂移措施自己漂移。
> 所以**同步必须按"文件"枚举，而不是按"我记得要同步哪个"**。

#### 唯一允许的差异（刻意的，不是漂移）

`~/.workbuddy/skills/…/SKILL.md` 的 frontmatter **多一行**：

```yaml
  agent_created: true
```

> ⚠ **上面这段示例故意缩进 2 格**：`^agent_created:` 只匹配行首，缩进后正文示例
> 就**不会**被"全文找这一行"的判定误认成真字段。少了这个缩进，
> 下面第 ② 条通用命令会报**假差异** —— 本技能真的因此栽过一次。

- 这是 WorkBuddy 标记"**模型自建技能**"的字段（决定该技能能否被模型直接修改）；
- **Claude Code 不用该字段**，仓库版也不写（保持中立）；
- ⚠ **同步时若不补回这一行，就会把 WorkBuddy 那份弄坏** —— 反之核对时若不忽略这一行，
  就会永远报"漂移"。
- ⚠ **判定"有没有这一行"必须限定在 frontmatter 内、且用整行匹配**。
  本技能**真的栽过**：§4.2 为说明这件事，把 `agent_created: true` 当示例贴进了正文 →
  "全文找这一行"的实现误判"标记已存在" → 同步时**不再补回** → **WorkBuddy 那份的标记真被抹掉了**。
  **教训：文档里出现的关键字符串会污染一切"全文搜索"式判定**；这类判定要限定作用域，
  并且**"缺少标记"本身也必须算失败**，否则会静默通过。

#### 本仓库附带的同步脚本（把"允许差异"编码进代码，不靠记忆）

> 下面这条**属于本仓库的便利工具**，不是技能包的一部分。换项目时按上表改路径即可
> —— 脚本靠**向上探测**找仓库根（认 `<repo>/skill/pcb-sch-cross-audit`），技能名之外无需改逻辑。

```bash
python hardware/afe_v0/tools/sync_copies.py           # 从真源同步到全部副本(自动补回 agent_created) + 核对
python hardware/afe_v0/tools/sync_copies.py --check   # 只核对; 有漂移 exit 1 (可挂 CI / 提交前自查)
```

脚本以仓库 `skill/` 为**唯一真源**，逐文件分发，并按"剥掉 `agent_created` 那一行后逐字节相同"判定，
输出每个副本的 md5 与结论。

> ⚠ **分发是单向的：真源 → 副本。改副本 = 没改。**
> 本技能**真的栽过一次**（2026-10-05）：给审计脚本补腰形槽支持时，改的是
> `hardware/afe_v0/tools/audit_pcb.py`（副本），随后跑 `sync_copies.py` ——
> 脚本忠实地用**真源那份旧代码**把副本覆盖了，5 处修复一起蒸发，
> 直到下一次跑审计时 `ValueError: could not convert string to float: 'oval'` 才暴露。
> **症状很有迷惑性**：同步脚本会打印"✓ 四份一致, 无漂移"——它说的没错，
> 四份确实一致，只是**一致地旧**。
> **规矩：只改 `skill/` 下的真源，改完再跑 `sync_copies.py` 往外发。**

#### 通用做法（不依赖任何脚本，任何项目都适用）

必须**两个文件都核** —— 只核 `.py` 正是本技能上次漂移的原因：

```bash
# ① SKILL.md · Claude Code 版 —— 应与真源逐字节一致
diff skill/pcb-sch-cross-audit/SKILL.md ~/.claude/skills/pcb-sch-cross-audit/SKILL.md   # 应无输出

# ② SKILL.md · WorkBuddy 版 —— 剥掉 frontmatter 里的 agent_created 后应一致
#    ⚠ 不能用 `grep -v '^agent_created:'`：它会连**正文示例**一起删掉 → 假差异。
#       作用域必须限定在 frontmatter（本技能 frontmatter 共 5 行）。
awk 'FNR<=5 && /^agent_created:/{next} 1' \
    ~/.workbuddy/skills/pcb-sch-cross-audit/SKILL.md \
  | diff - skill/pcb-sch-cross-audit/SKILL.md                                           # 应无输出

# ③ audit_pcb.py —— 比内容，**不要比字节**
#    ⚠ `md5sum` 对换行符敏感；本仓库 .py 本身就是 19 个 LF + 19 个 CRLF，
#       用它判定会长期误报"漂移"。剥掉 \r 再比。
diff <(tr -d '\r' < skill/pcb-sch-cross-audit/reference/audit_pcb.py) \
     <(tr -d '\r' < hardware/afe_v0/tools/audit_pcb.py)                                 # 应无输出
```

> 📌 **判据的两条要求**（本技能两处都栽过）：不但要**能抓到错**，
> 还得**不误报** —— 会误报的检查会被人学会无视，等于没有。
> **`sync_copies.py --check` 已把这两点都实现（含换行符归一 + frontmatter 作用域），以它为准。**

> 📌 **同类前例（本仓库实测）**：同一目录下的 `kicad-sch-codegen/` 漂移得更远 ——
> 仓库版与 Claude Code 版是 307 行（md5 一致），而 WorkBuddy 版只有 **44 行**（浓缩稿）。
> 所以"副本不一致"不只是措辞差异，**可能是差了一个数量级的内容**：
> WorkBuddy 每次会话加载的是那份 44 行的，Claude Code 加载的是 307 行的。
> **加文件/删文件时尤其危险** —— 新增文件不会自动进入任何同步动作。

## 五、报告写法

- **先给结论**：网络层面是否对得上？只有"逐焊盘 0 差异"才能下"对得上"的结论
- **第 ④ 项要单独给结论**：直接引用 `【2b】▶` 那一行（"文本标注与焊盘网络全部一致" / "N 处不符"），
  不要只说"丝印看过了" —— 否则读者无法区分"工具查的"和"人眼看的"
- 问题按 🔴必须改 / 🟡需知悉 / 🟢建议 分级，每条给「位置 + 为什么危险 + 怎么改」
- 改动识别要区分"人改的"与"生成器写的"
- 若根因在生成器表，必须写明**改两处**（生成器 + 成品板），否则重跑生成器会还原
- 附原始输出文件，便于复核

## 六、已验证的效果

在一次双通道模拟前端 PCB 交付审计中（49 封装 / 101 焊盘 / 21 网络）：

- 网络对应性：**20 个有效网络逐焊盘 0 差异**，位号集合、引脚数↔焊盘数全部一致
- 查出 **1 处真缺陷**：两个测试焊盘的**文字与网络互换**（板上写 `V_VB`，实际焊盘在 `V_OUT` 网上）——
  网络表比对**查不出**这类错；若未查出，调试时会按丝印探到错误节点、把偏置调到错的点上
- 查出 **1 处占位封装**（`GENERIC_NEEDS_VERIFY` 的耳机座）需换真件
- 几何/间距/丝印压盘检查全过，工具自身经"修 3 条并查集规则"后从 6 处假差异收敛到 0

### 6.1 第 ④ 项的回归验证（说明它确实自动生效）

拿审计前的备份文件当"病人"跑，与修复后对照：

| 对象 | 【2b】第④项结论 |
|---|---|
| `…_preaudit.kicad_pcb`（缺陷版） | **⚠ 4 处**：value 文本 2 处（`TP6`=V_VB / `TP7`=V_OUT）+ 板级丝印 2 处 |
| 修复后版本 | **✓ 0 处**，8 条测试盘丝印逐条自证（如 `V_VB (= VBIAS_V) 最近焊盘 TP7.1`） |

### 6.2 第 ④ 项自己踩过的坑：**别做过度归一化**

第一版把 `_`、空格、`+` 全部抹掉再比对，结果把**分区标题 `V IN`** 误判成网络 `V_IN` 的标注，
凭空报 1 处假阳性（它旁边是 J2 的地脚）。

> **教训**：网络标签是按网络名**原样书写**的，而分区标题是**人写的散文**。
> 判定"这段文字是不是网络名"时必须**下划线/空格敏感**（只归一化大小写），
> 否则会把 `V IN` / `CT IN` 这类标题卷进来。**假阳性比漏报更浪费人** —— 会让人去改一块本来正确的板。

（该分支已在代码注释中写明，防止后人"顺手优化"时又把它抹平。）

## 七、失效条件

- **无法证明"设计意图本身是对的"**：本审计只验"PCB 与原理图一致"，两者同错时一致照样通过——
  仍须拿设计文档逐条核对（与 `kicad-sch-codegen/` 的"只验实现、不验意图"是同一类边界）
- 前提是**手上有原理图源文件**；只有 Gerber / 图片时退化为人工比对，不能自动查网络
- 第 2 项比对依赖"生成器脚本存在且其表就是意图"。**PCB 是纯手工画的、或生成器已过期**时，
  第 2 项会把所有手工改动报成"差异"（此时它反而变成"手工改动清单"，需人工判性质）
- **第 ④ 项只能校验"文字本身就是网络名"的标注**（测试盘、网络标签）。若丝印写的是自由描述
  （如 `CT in`、`3V3<-J5-35`），工具无法判断它是否与网络相符 —— 这部分仍要人眼过一遍 §六 的丝印清单
- 第 ④ 项按**几何就近**归属板级丝印（阈值 8mm）。元件排布极密、丝印离开所属焊盘超过阈值时，
  该条会被当作"分区标题"跳过（保守选择：宁可漏报也不误报）
- 不做电气正确性（如运放接法是否适用）、不做布线质量与 SI 评估
