# 用大模型调硬件 · 踩坑清单

## 何时用

- 模型给出了一个**听起来很有道理**的因果解释，但你没有实测验证过
- 你的自检工具报了绿灯（ERC / DRC / lint / `audit()` / 单元测试），但电路/代码**还是不工作**
- **模型从一批实测数据里"发现"了一个漂亮的规律**（某个占比、某个相关性），你没有验证过它
- 反复排查同一现象，每次换一个假设，都推翻
- 准备写"结论"或"机理"进报告时

**不适用**：纯数字逻辑的综合时序问题（用仿真和时序报告）、需求本身不明确（那是需求问题不是调试问题）。

---

## 一、核心命题：为什么"自检通过"会骗人

**三类假阳性，根因是同一个。**

| 假阳性 | 检查器 | 共享的错误假设 |
|---|---|---|
| ERC 报 **0 错 0 警**，但钳位二极管接错了位置 | 自己写的 `EXPECT` 网络表 | `EXPECT` 表是按作者（错误）的意图写的 |
| `audit()` 报**悬空 0 个**，但元件值抄错、位号编错 | 引脚-导线接触检查 | 只验连接拓扑，不验数值与设计文档的对应 |
| 模型给出**自信的机理解释**，但现象根本不存在 | 语言模型 | 模型与你共享了同一个错误前提 |

**共同结构**：检查器与被检查对象由**同一个作者、基于同一份理解**产出 → 两边一致地错 → 检查通过。

```
       意图（可能是错的）
          ↓ 写
      EXPECT / 断言 / audit 规则
          ↓ 校验
       实现 ────────→ ✅ 通过
          ↑
       同一个作者写的
```

> ### 结论
> **自检工具只能抓「实现与意图不一致」，抓不到「意图本身就是错的」。**
> 要抓后者，只能拿**外部锚点**对照 —— 设计文档、实测数据、独立推算。

**可操作的推论**：每加一个自检工具，同时问一句"这个工具的期望值是谁定的？如果我的理解错了，它还能报警吗？"

## 二、五条判据

### 判据 1：先算清基本方程，再谈"异常"

**实测案例**：断开交流信号源后，输出直流平均值从 500 mV 掉到 300 mV，模型判为"整流效应"。
实际是 `Vout_DC = Vbias × (1 + Rf/(R1+R2))` —— 断开信号源后 R1 悬空，直流增益本就不同。
**这是正常现象，不是异常。**

→ 看到"异常"先把理论值算一遍。**先算方程，再谈异常。**

### 判据 2：模型给因果解释时，先问"这个现象本身是真的吗"

一次完整的 8 步排查中，模型连错 6 次，**每一次都由实测推翻，没有一次是被再推理推翻的**：

| # | 模型的假设 | 实测结果 | 根因 |
|---|---|---|---|
| 1 | 钳位二极管接在 R1-R2 之间 | 接在虚拟地，位置正确 | 没确认实际接线就推理 |
| 2 | "avg 变 300" 是整流效应 | 正常的直流增益差异 | 过度解读，没先算方程 |
| 3 | 输出最低点存在 Vmin 临界约束 | 不存在，只看 RV2 | 预设了错误的变量 |
| 4 | 中点与增益相互独立 | 公式错，RV1 也影响 Avg | 凭印象写公式，没写全 |
| 5 | 容性负载自激（C4 导致） | 拔掉 C4 波形不变 | 假设未经验证 |
| 6 | 负载电阻放 R3-R4 之间更优 | 临界点反而上移 | 分压推算被实测推翻 |

> **模型的错误只能被数据推翻，不能被讨论推翻。**
> 与模型反复讨论同一个假设，是纯浪费 —— 去拿一个测量值回来。

### 判据 3：每个排除步骤必须有可判定的判据

- "换了同型号芯片，波形不变" → 才能排除**个体差异**
- "拔掉 C4 波形不变" → 才能排除**容性负载自激**
- "拔掉钳位管波形不变" → 才能排除**钳位管整流**

**判据不明确的排除 = 没排除。**

→ 做实验**之前**先写下："如果结果是 A，就排除原因 X；如果是 B，就排除原因 Y。"

### 判据 4：模型自己造的判据，先拿「已知答案的对照组」验一遍

**这是判据 2 的镜像**：判据 2 说的是"自检工具会共享你的错误假设"，
判据 4 说的是**模型自己临时发明的分析判据，也会共享模型的错误前提**。

**实测案例**（`reference/case-2026-10-04.md`）：模型提出「非锁相残差」判据 ——
把电流拆成"与市电锁相的分量"和"残差"，残差记为混进来的干扰。
在一个手机充电器上跑出"24 % 的功率不是负载电流"，在充电板上 34~78 %。**结论看起来很漂亮。**

**把它用在已知答案的样本上（无载帧 = 纯噪声，真值 = 零信号）：**

```
无载帧(纯噪声)    残差谱: 0.8 / 0.8 / 0.8 / 0.8 / 0.8 mA   ← 平的
charger3  ★苹果   残差谱: 7.4 / 9.9 / 13.0 / 14.8 / 15.3 mA
pad1      ★苹果  残差谱: 27.2 / 30.3 / 23.6 / 22.2 / 19.8 mA
laptop_02        残差谱: 2.5 / 4.3 / 5.1 / 6.2 / 6.4 mA
无载帧(对照)      残差谱: 0.8 / 0.8 / 0.8 / 0.8 / 0.8 mA
```

**"随谐波阶次递增"这个形态在苹果、非苹果、对照组三边同时出现 → 判据本身有系统偏差。**

→ **任何模型自造的分析判据，先在一个"已知答案"的样本上跑一遍。**
**对照组也报警的判据 = 假判据。** 这一步花 1 分钟，能省掉一整轮错误结论。

> 对照组从哪来：噪声段、空载段、已知物理真值的阻性负载、
> 或者任何"如果判据是对的，它必须给出某个特定答案"的样本。

### 判据 5：优先用数据自带的 null

**采集场景本身往往包含一个"激励关掉、测量链路完全不变"的时段** ——
它就是最干净的参考，比任何事后推理都可靠。

**实测案例**：60 s 采集记录里，前几秒设备**没有通电**。这几秒直接给出：

| 量 | 插着电源砖、未通电 | 拔掉电源砖 |
|---|---:|---:|
| 电流通道交流 RMS | **43.3 mA** | 19.0 mA |
| 其中 50 Hz 分量 | **54.1 mA** | **2.2 mA** |
| 基波占总功率 | **78.0 %** | 0.7 % |

**一眼看出：设备没开机，电流通道里却有与市电同步的 40 mA —— 这是加性拾取，不是噪声。**

→ **设计采集流程时，主动保留一段"激励关、链路不变"。**
（如充电器类设备：电源砖插在电网上但不充电；电机类：断电但接线不动。）

## 三、排除法流程

```
1. 列出所有可能原因
2. 每次只改一个变量              ← 改两个，结果无法归因
3. 动手前写清楚本步的判据         ← "什么结果排除什么"
4. 记录结果，包括"无变化"         ← 无变化也是数据
5. 全部排除完仍未定位 → 见第四节
```

**步骤数不是目标。** 8 步里 5 步是实测做的、3 步是模型猜的 —— **价值全在实测那 5 步**。

---

## 四、"不可复现"是合法结论

不要为了交差编一个无法验证的机理。

**推荐写法**（实测采用）：

> **问题**：面包板实测发现运放输出在低电平时波形出现"鼓包"畸变
> **排查**：8 步逐项排除（换同型号芯片复现 / 拔钳位管 / 拔抗混叠电容 / 反馈补偿 / 电源轨 / 增益无关 / 直流相关 / 负载相关）
> **结论**：与输出负载条件相关；**现象不可复现**，未能定位到稳定机理
> **处理**：采用实测验证有效的输出负载方案 + 保留工作点余量
> **效果**：两通道波形干净，量程利用率 66~78%

**为什么这样写更好**：答辩时"为什么给不出确切机理"有明确答案（现象非确定性），
而编造的机理一旦被追问细节就会穿帮。**诚实记录比编造机理更专业。**

## 五、仿真的边界（别让仿真给你虚假信心）

| 仿真能验 | 仿真**不能**验 |
|---|---|
| 拓扑错误（接到错的节点） | 运放驱动容性负载会不会自激 |
| 参数错误（增益算错、削波） | 真实的轨到轨输出极限 |
| 离电源轨余量 | 面包板接触电阻 / 寄生参数 |
| 静态工作点 | 传感器真实特性、投切瞬态过冲 |

> 仿真里运放是**理想模型**、信号源是**理想正弦**。
> **仿真负责扫掉"拓扑和参数级"的错误，剩下的只能靠实测。**

**这是判据 2 的另一种表现**：仿真器与你有同样的理想化前提，所以它验不出前提的错误。

## 六、改写模型输出的自查表

模型给出一段机理解释后，逐条过：

```
□ 这个"现象"是实测观察到的，还是模型从原理推出来的？
□ 基本方程算过没有？理论值是多少？
□ 这个解释有没有一个能被单次实验否定的判据？
□ 如果我的前提本来就是错的，这个解释还成立吗？
□ 有没有一个更简单的解释（比如"本该如此"）？
```

**任何一项答不上来，就不要把它写进报告。**

## 七、已验证的效果

| 指标 | 结果 |
|---|---|
| 模型连续错误次数 | 6 次，全部由实测纠正 |
| 用户侧独立贡献 | 7 项（见 `reference/case-2026-09-28.md` 第四节），**包括唯一有效的解法** |
| 最终成果 | 两通道调通、相位差 0°、量程利用率 66~78% |
| 省下的返工 | 交付前逐条核对设计文档，抓出漏画的 R12（见下） |

**同类坑的第二次命中**：同一项目里，ERC 输出 0 错 0 警，但钳位二极管 D1~D4 被误接在
R1 与 R2 之间（应在虚拟地）—— 只有数值仿真发现（电流通道 THD 11.4%、电压通道 THD 39.1%）。
**这就是第一节"共享错误假设"的另一个实例，不同工具、同一个根因。**

**第三次命中（不同形态）**：模型从实测数据里造了一个判据，
在一个样本上给出"24 % 的功率不是负载电流"的漂亮结论；
把它用在**已知答案的对照组**（纯噪声帧）上，对照组也报警 → 判据作废，
连带撤回了一整张表。**见判据 4 与 `reference/case-2026-10-04.md`。**

| 指标 | 结果 |
|---|---|
| 2026-10-04 被推翻的模型结论 | **4 个**：自造判据 A（整张表）、判据 B（作为主因）、"苹果 PF 高"假设、品牌标注 |
| 其中被**模型自己**推翻的 | 3 个（判据 A 由自检推翻；其余两个由实测数据推翻） |
| 被**用户补的数据**推翻的 | 1 个（判据 B —— 用户补上第二组功率计读数，暴露台架重复性只有 ±3~5 %） |
| 最终收敛 | 根因 = 被夹住的火线对无屏蔽 CT 的**容性耦合**（加性，0~35 mA）；**测量链本身被验证**（扣本底后与功率计差 −0.5 %） |

> ⚠️ **本案例暴露的一个盲区**：模型**不会主动怀疑自己刚测出的那个数**。
> 直到用户补上第二组数据，才发现"同设备同工况两次采集差 4.9 %"。
> **每次下结论前，先问一句："我用来下结论的这个量，它自己稳不稳？"**
