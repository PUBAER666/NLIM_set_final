# KiCad 原理图程序化生成 + 自校验 + 交付

## 何时用

先分清要哪种产物，**几条路线不要混**：

| 产物 | 谁看 | 走哪条 | 能干什么 |
|---|---|---|---|
| **PNG 图** · 模拟小电路 | 人 | `schemdraw`（用法见文末分工表） | 最省事、最好看，但**不检查连接** |
| **PNG 图** · 多引脚 IC / 要自检 | 人 | `reference/schematic_dsl.py`（matplotlib） | 坐标可控，`audit()` 能查悬空引脚 |
| **KiCad 工程 zip** · 嘉立创**标准版** | EDA 软件 | 生成 v5 legacy 三件套（`.pro`/`.sch`/`-cache.lib`） | 已验证可行，导入后可编辑、转 PCB |
| **KiCad 工程 zip** · 嘉立创**专业版** | EDA 软件 | 生成 **KiCad 6 `.kicad_sch`（符号全内嵌）** + `.kicad_pcb` | ⚠️ **legacy `.sch` 导专业版会丢光元件**，见下节 |

- **只想"看图/讲清楚电路"** → 出 PNG，不要碰 KiCad 那套
- **要打样/给代画店/交付可编辑工程** → 出 KiCad zip；**先问是标准版还是专业版**
- 两个都要也很正常：PNG 用来讨论，zip 用来交付
- ❌ **不要手写 EasyEDA JSON**：格式无公开稳定规范，风险过大，别走那条路

## 环境准备（中国大陆 Windows 常见坑）

### ⚠️ 先确认 Python 解释器绝对路径

**不要用裸 `python` 跑本技能的脚本。** Windows 上裸 `python` 经常命中**微软商店的占位符**（一个假 `python.exe`，运行时弹应用商店），命令会直接失败且报错莫名其妙。

```bash
# 先找到真实解释器
where python
# 确认可用后，之后一律写全路径，例如：
D:\Dev\Python314\python.exe tools/gen_kicad.py
```

### ⚠️ 非 ASCII 输出要设 PYTHONUTF8

Windows 控制台默认 GBK。脚本打印 emoji 或某些符号会 `UnicodeEncodeError`：

```bash
PYTHONUTF8=1 D:\Dev\Python314\python.exe tools/erc_check.py
```

### 依赖

**出 PNG：只要 matplotlib，本机已装，无需新增任何依赖。**

出 KiCad zip 也一样（纯标准库）。只有走备选的 schemdraw 渲染才需要：

```bash
pip install schemdraw
```

**清华源有 schemdraw，不用特意走 pypi.org。**（若 pip 已配国内镜像，直接装即可。）

matplotlib 画中文要先设字体，否则全是方框（`schematic_dsl.py` 里已设好）：

```python
import matplotlib
matplotlib.rcParams["font.sans-serif"] = ["Microsoft YaHei", "SimHei", "sans-serif"]
matplotlib.rcParams["axes.unicode_minus"] = False
```

## KiCad v5 legacy 格式要点

1. **三件套**：`xxx.pro`（工程，可极简）、`xxx.sch`（`EESchema Schematic File Version 4`）、`xxx-cache.lib`（`EESchema-LIBRARY Version 2.4`，**自包含全部符号**，导入不依赖外部库）
2. **导线行**：`Wire Wire Line` 下一行 `\tx1 y1 x2 y2` —— **必须空格分隔**。用 `%-5d` 定宽格式化，坐标到 5 位时会粘连成 `104503300` 这种废数据
3. **元件矩阵**：2×2 仿射，`NAT=(1,0,0,1)` `CW=(0,-1,1,0)` `CCW=(0,1,-1,0)` `R180=(-1,0,0,-1)`，映射 `(x,y)→(ax+by, cx+dy)`；lib 坐标 y 向下与图纸一致
4. **多单元符号**（如双运放：2 个运放单元 + 1 个电源单元）：lib 里 `X` 行第 10 字段是**单元号**（`X name num x y len orient 50 50 unit 1 etype`）；`.sch` 里 `U n 1 ts` 行标单元；**每个单元一个 `$Comp`**。
   > **漏了单元号，所有单元的引脚会全部算到第一单元头上** —— 这是最容易犯、最难查的错
5. **连接**：交叉连接放 `Connection ~ x y`；不连的引脚放 `NoConn ~ x y`；标签 `Text Label x y orient ~ 名字`
6. **封装字段**：`F2` 填 KiCad 官方封装名**占位**（如 `Resistor_THT:R_Axial_DIN0207_...`），README 里声明导入后需重新绑定立创封装

## 嘉立创EDA **专业版** → 必须走 KiCad 6 `.kicad_sch`（2026-10-05 实测）

### 失败症状先记住

把 v5 legacy 三件套打包导入**专业版**，结果是：
**原理图上只剩导线 / 结点 / 注释 / 文字标签 —— 元件符号、位号、数值全部消失。**

原因：专业版只认 KiCad 的这几种后缀
`*.zip, *.lib, *.kicad_sch, *.kicad_pcb, *.kicad_sym, *.kicad_mod, *.mod`
—— **legacy `.sch` 不在列表里**。文档写的"支持 KiCad 5.1 和 5.9"实为：
**5.1 指 PCB（`.kicad_pcb`）、5.9 指原理图（`.kicad_sch`，KiCad 6 的内部版本号）**。
legacy `$Comp` 引用的 `-cache.lib` 专业版解析不到 → 元件被整块丢弃；
不依赖库的导线/标签/注释照常显示，所以症状不是"导入失败"而是"少了东西"。

### `.kicad_sch` 关键格式点

1. 文件头：`(kicad_sch (version 20211123) (generator eeschema)`；坐标 **mm**
2. **符号定义内嵌**在 `(lib_symbols ...)` 段里（这就是它不需要 cache.lib 的原因）
3. 子符号名 `<符号名>_<unit>_<convert>`（如 `R_0_1` 放图形、`R_1_1` 放引脚；unit 0 = 各单元公用）
4. 实例：`(symbol (lib_id "库:名") (at x y 角度) (unit n) (in_bom yes) (on_board yes) (uuid ...)`+ 四个 `(property ... (id N) ...)` + 每个引脚 `(pin "n" (uuid ...))` + `(instances (project ... (path "/<根uuid>" (reference ...) (unit n))))`
5. 引脚名 `~` = **无名引脚**（KiCad 6 就是这么写的，别改成空串）
6. **0 长度引脚要发 `hide`**（电源符号的引脚）—— 否则引脚名（"GND"/"+3V3"）会被多画一份压在符号上

### 坐标与旋转（最容易错的地方）

- 模型（legacy，y 向下）→ 文件（库 y **向上**）：**库符号发射时对 y 取反**，实例不加 `mirror`，两侧约定相抵
- 旋转角：eeschema 存储角是**视觉逆时针**。由纯几何推导（库点 → 文件系 → 逆时针转 A → 翻回 y-down）：
  **视觉顺时针(CW) ↔ A=270，视觉逆时针(CCW) ↔ A=90**（R180↔180，NAT↔0）
- ⚠️ **这里最险的坑**：角度写反时，如果校验代码用了**同一套错公式**，自检会**全绿**——
  生成器与校验器共享错误约定 = 假绿。**校验公式必须独立推导或锚定外部真值**
  （本次锚点：KiCad 官方文档"角度逆时针" + legacy 版在标准版里实测视觉正确）
- 引脚朝向映射：legacy `R/U/L/D` → 文件 `0/90/180/270`（两者视觉语义一致，y 取反只影响坐标不影响朝向）

### 复用既有 legacy 生成器（别重写电路）

既有生成器常常**不能 `import`**（emit 逻辑在模块顶层，import 即重写产物目录）。
做法：**`exec` 它的源码前缀到"发射"标记为止**，取到内存模型后自己出另一种格式：

```python
src = io.open(SRC_GEN, encoding="utf-8").read()
prefix = src.split("# ===================== 发射: cache.lib")[0]   # 不含任何写盘代码
ns = {"__name__": "_model", "__file__": SRC_GEN}
exec(compile(prefix, SRC_GEN, "exec"), ns)      # ns["SYMS"], ns["comps"], ns["wires"], ns["P"]...
```

好处：**与已审计过的旧产物完全同源**，电路不会因为"换个格式"而漂移。

### 文字布局：程序化出图必须自己做避让

legacy `.sch` 习惯把实例字段**一律钉在固定偏移**（如 `(x+150, y-200)`、左对齐）——
在密集区必然压字；把**库内 F0/F1 的默认偏移**当实例位置更糟（直接压在符号本体上）。

推荐做法（可验证，不靠眼力）：
1. **默认位**用 KiCad 惯例：位号在本体**上方居中**、数值在**下方居中**（电源符号的数值居中放上方）
2. 算每个字的**包围盒**：宽 ≈ `0.85 × 字号 × 字符数`（全角按 1.7 倍），高 = 字号
3. 候选位按距离展开（上/下/四角/左右，逐级外推），**打分选择**：
   `(硬冲突数, 距离 + 2×压导线数)` —— 硬冲突优先，其次尽量不压导线，最后才比远近
4. 顺序：标签（锚点在导线上，**不可挪**）→ 注释（可小幅平移，保住"标注的是哪一块"）→ 位号/数值
5. **多单元器件**的字段必须按**实例 key** 索引，不能按位号索引——否则两个单元的字段互相覆盖，出现两份同位号的叠字
6. **图框边界也要当硬冲突**（见下）——"不重叠"≠"看得见"

#### 别漏了图框边界（真实踩坑）

**改一句注释文案就能把布局搞坏。** 实测：一条注释从 36 字改成 63 字后，
包围盒宽从 1836mil 涨到 3213mil，**顶出 A4 右边框 5.4mm** ——
而"文字零重叠"自检**完全查不出**这类问题（它只管文字之间，不管图纸边界）。

做法：A4 横向 `297×210mm`，KiCad 默认 drawing sheet 四边各留 **10mm** 页边距。
把四条边距做成**巨大的矩形"墙"**，直接追加进避让用的障碍盒列表（gap=0），
于是"顶到框线"与"压元件本体"在打分里同级 —— 不用改打分函数，白嫖现有机制：

```python
SHEET_W, SHEET_H, SHEET_M = 297.0, 210.0, 10.0
_BIG = 1000.0
def frame_walls():
    W, H, M = SHEET_W, SHEET_H, SHEET_M
    return [(-_BIG,-_BIG,M,H+_BIG), (W-M,-_BIG,W+_BIG,H+_BIG),   # 左右
            (-_BIG,-_BIG,W+_BIG,M), (-_BIG,H-M,W+_BIG,H+_BIG)]   # 上下
ob_boxes = [o[3] for o in obstacles] + frame_walls()   # 只给文字布局用
```

两条配套经验：

- **长文案要额外给"整段左移"候选**：常规注释候选只有 ±13mm 上下平移，宽注释退不开。
  补一组步进 12mm 的横向候选（`dx = -12, -24, … -84`），并把越框计入硬冲突 → 自动左退进框。
- **哑发射器（legacy `.sch`）没有避让引擎**：它把注释钉死在源锚点上。
  所以**源头锚点本身就必须合法**，别指望下游兜 —— 给两个格式各留一份合法性，
  而不是只修其中一份。

### 四道自检（都别省）

| # | 查什么 | 怎么查 |
|---|---|---|
| ① | 引脚坐标没漂 | 回读文件，按 `sheet = P + (cA·lx − sA·ly, −sA·lx − cA·ly)` 重算每个引脚绝对坐标 → 与模型逐个比对 |
| ② | 网络表没变 | 两侧各自跑并查集重建网络表（规则同 ERC-lite）→ 逐网络比对成员集合 |
| ③ | 文字不打架 | 从**文件**里读可见文字重算包围盒 → 两两不重叠、且不压元件本体/引脚文字 |
| ④ | 文字不出图框 | 同一批包围盒 ↔ A4 有效区 `[10, 287] × [10, 200] mm`，任一条越界即 `exit(1)` |

> ③ 和 ④ 要分开做。③ 过了只说明"文字之间不打架"，**文字可以整条跑到图纸外面去**。
> 任何"文字盒"相关的断言，都要同时问一句：**它还在纸里吗？**

### 导入前先看图（`render_sch_preview.py`）

嘉立创/KiCad 里没有"我能不能先看一眼"。预览脚本独立解析 `.kicad_sch`
（库符号 + 实例 + 导线 + 结点 + 文字），按同一套变换画到 A4 画布上，
把每段文字**框出来**——于是"有没有压字、文字有没有飞太远"在导入前就能肉眼验收，
不必来回导入导出试错。支持 `--zoom x1,y1,x2,y2` 放大密集区。

### 别手改成品：改编辑器 ≠ 改了工程

生成器产出的 `.sch` / `.kicad_sch` 会被原样导入 EDA 工具，于是很容易在**编辑器里直接改**文案/数值。
**那是成品，不是源头** —— 一旦重生成，手改内容全部退回。正确顺序永远是：

```
改源头(generator) → 重生成 → 重新打包 → 重跑校验/审计
```

判断"哪里才是源头"的硬办法：**看谁会被脚本覆盖**。本次实例中
`gen_kicad.py` 只写 `kicad/*.sch|.pro|.lib + *_kicad.zip`，**不碰 `.kicad_pcb`** ——
这条"写盘范围"在动手前用 `grep -n "open(\|\.lib\|\.sch\|\.pro" gen_*.py` 一查就知道，
能提前避免误伤已交付的制板文件。

配套：改完源头**必须重跑交叉审计**。本次改了原理图 J4 的 value，
审计立刻报出 `⚠ J4 原理图=… PCB=…` —— 这正是"审计在干活"，
而不是"审计坏了"；要么同步 PCB 侧生成器并重生成（注意 `.kicad_pcb` 是已交付件，要先确认能不能动），
要么把差异**显式写进审计报告并说明理由**。

### 失效条件（诚实说明）

- 文字宽度是**估算**（0.85×字号×字符数）。换成非等宽 / 奇异字体的渲染器，边界情况仍可能贴脸
- 障碍建了"元件本体 + 引脚名/号 + 导线 + 图框四条边距"，但**注释与注释之间**若刻意重叠不会自动分开
- 避让只会在候选位里找，**全撞时取最轻**并打印告警 —— 看到"无解"要人工看一眼
- **页边距按 KiCad 默认 10mm 硬编码**。若目标工具用的是别的 drawing sheet（或 A3/A5），
  边界值要跟着改，否则自检④会误判

## ERC-lite（并查集，强烈推荐）

**生成器再小心也会出坐标错误，必须用另一套逻辑独立校验。**

1. 解析 `.sch` + `-cache.lib` → 所有引脚**绝对坐标**、导线、`Connection` 点、标签、电源符号、`NoConn`
2. 并查集合并：导线两端、**端点落在导线线段中点（T 型搭接，最易漏）**、同名标签、同名电源
3. 校验项：
   - `EXPECT` 命名网络成员集合**精确比对**（`I_IN`/`GND`/`+3V3`…）
   - **内部节点纯度**（不多不少，一个引脚都不能混入）
   - 悬空 = 单引脚且无电源/标签/导线
   - NC 引脚必须完全隔离
   - 同名标签**先查冲突再合并**（两个不同网络被命名成同一个名字，是隐蔽的短路）
4. 改连线后**先同步校验器里的 `EXPECT`/`INTERNAL` 表**再跑；目标 **`ERRORS: 0, WARNINGS: 0`**
5. **实测收益**：ERC 驱动调试连抓 51 → 14 → 0 三类真 bug（单元号硬编码、坐标粘连、图元碰撞）

> ⚠️ **ERC 通过 ≠ 画对了。** 校验器里的 `EXPECT` 是**你自己写的期望值**，它验证的是"生成器输出 == 你的意图"，**不是"你的意图 == 设计文档"**。所以下一节不能省。

## 交付前对照设计文档逐条核对

**"画完了" ≠ "画对了"。**

生成器只保证"我按你说的画了"，不保证"你说的是对的"，更不保证"你漏说的它也画了"。

> **实测案例**：交付前把设计文档逐节过一遍，抓出**漏画的 R12**（0Ω 保险电阻）。ERC 不可能报这个错——因为校验器的期望表里也没有它，两边一致地错。**这一条省了一次打样。**

**做法**：拿设计文档，按"接口定义 → 每级电路 → BOM"的顺序，逐条在原理图里找对应物，找不到就记下来。

## 备用/未用器件的处理（容易埋雷）

**未用的运放单元、门电路、比较器，输入端绝对不能悬空。**

输入悬空的运放：输出会在电源轨之间乱摆/自激 → **把开关噪声灌进电源轨** → 如果那条轨是模拟基准，**直接污染整个测量系统**。

两种处理，**建议都做**：

| 处理 | 做法 |
|---|---|
| **原理图上接好** | 接成**跟随器**：`+输入 → GND`（或中点），`−输入 → 输出` |
| **实物上声明** | 在 README/BOM/丝印三处都写明"此位不焊"，**尤其配了 IC 座时**——因为 IC 座的存在就是邀请别人插上去 |

> ⚠️ 只在 README 里写一句"可不焊"**不够**。配了 IC 座 + 只写一句说明 = 迟早有人插上芯片然后踩雷。
> 丝印上也要标。

## 出 PNG · 路线一：matplotlib 手搓符号（多引脚 IC / 要自检时用）

> 小型模拟电路优先用 schemdraw（下一节），更省事也更好看。
> 这条路线的不可替代之处是 **`audit()`** 和**标注位置完全可控**。

**为什么不用 schemdraw**：它的自动布局对模拟电路（运放 + 反馈 + 偏置支路）很不听话，
而且自带 4 个大坑（见文末）。手搓符号虽然土，但**坐标完全可控**，且只要 matplotlib
—— 本机已装，零新增依赖。

### 三条设计约定（破坏任何一条，自检就废了）

1. **每个符号函数都返回它的引脚坐标。** 调用方一律用返回值连线，不要手写坐标。

   ```python
   op = opamp(ax, 90, 84, 6, 'U1A')
   wire(ax, [(84, 90), op['in-']])        # ✅ 用返回的引脚
   wire(ax, [(84, 90), (90, 90)])         # ❌ 手写 —— 和引脚对不对得上全靠运气
   ```

2. **符号内部引线用 `_seg()`，用户连线用 `wire()`。** 只有 `wire()` 会往自检表里
   登记端点。若符号内部也用 `wire()`，符号自己的引线会把引脚检查变成**永真**。

3. **每个符号的引脚通过 `_pin()` 注册**，画完调 `audit()`。

### audit：这个 DSL 存在的主要理由

```python
audit_reset()                    # 画新图前清空登记表
render(lambda ax: draw_channel(ax, CH_I), 'out.png', ...)
audit()                          # 打印悬空引脚
# 引脚 43 个，导线 30 段，悬空 0 个
```

它检查每个引脚是否被导线端点、导线中段（T 型搭接）、或另一个引脚接触。

> ⚠️ **audit 通过 ≠ 画对了。** 它只验证「引脚都被接上了」，
> **不验证接法是否符合设计意图** —— 后者仍要靠拿设计文档逐条核对（见上文）。

**它抓不到的（实测踩过）**：

| 抓不到 | 后果 | 怎么办 |
|---|---|---|
| 导线从符号身上穿过去 | 图很乱，读者以为短路 | 肉眼过一遍；绕线走符号外侧 |
| `dot()` 放在没有分支的地方 | 读者以为那里有分支 | 实心点**只在真分支处**放 |
| 比例失调（运放相对电阻过大） | 能读但难看 | 先定信号电平，再反推 `hh`/`yc` |
| 元件值抄错、位号编错 | 电路功能错 | 拿设计文档逐条核对，**这条只能靠人** |

**实测收益**：本技能第一次跑 audit 就抓到运放符号画在 `yc±hh`、导线却接在别的
y 上，**差 6 个单位**。图上两条线搭在三角形斜边上，符号内部的 `−`/`+` 字又恰好
靠近导线 —— **肉眼完全看不出**，但它就是没接到引脚。这就是"符号函数不返回引脚
坐标"的必然结果。

### 画图约定

- **一张图一个模块**。电流通道 / 电压通道 / 电源各出一张。单张大图必然标签打架。
- **`axis_setup()` 里 `set_aspect('equal')` 必须开**，否则电阻会被拉成细长条。
- **中文字体必须显式设**，否则标题和注释全是方框：
  ```python
  plt.rcParams['font.sans-serif'] = ['Microsoft YaHei', 'SimHei', 'sans-serif']
  plt.rcParams['axes.unicode_minus'] = False   # 负号也会变方框
  ```
- **想突出差异就把元件标红**（`draw_channel(ax, CH_V, hot={'R6','R11'})`）。
  双通道电路讲"这两路哪里不一样"，比文字说明有效得多。
- 符号几何尺寸是**图纸单位**不是毫米，靠 `xlim/ylim` 整体缩放。

### 踩过的坑

- **连接器引脚端点在 `x+w+6`，不是框边**。写 `wire(ax, [jp['TIP'], (x+w, y)])`
  会变成一条从框边到引脚端的线；写成 `(x+w, ...)` 两头一样则产生**零长度线段**，
  自检会报悬空。
- **改符号高度会让引脚位置跟着变**。运放那次的教训：`hh` 一改，
  所有连线 y 都要重算 —— 所以引脚坐标**必须**从返回值取。
- **`vcc()` 的 `h` 要按场地给**。默认 6；电源轨那种长引线给 20；
  被上方信号线挤住时给 4（原注释：3V3 顶端必须低于主信号线，否则引线交叉短路）。

## 出 PNG · 路线二：schemdraw（小型模拟电路优先）

**schemdraw 画得比手搓好看**（美式锯齿电阻、空心圈网络标号、教科书级运放），
加一种新符号只要一行 `elm.Xxx()`。**但它不检查任何电气连接。**

| 场景 | 用哪个 | 为什么 |
|---|---|---|
| 小型模拟电路（分压 / 运放级 / RC 滤波 / RLC） | **schemdraw** | 快、好看、库自带 226 个符号 |
| 多引脚 IC（AD7606 这种） | **手搓 DSL** | `elm.Ic()` 对引脚标注**不避让、不报警** —— 实测叠字废图 |
| 要「没接上引脚」能自动查出来 | **手搓 DSL + `audit()`** | schemdraw 没有等价能力 |
| 增量改动（支路中间串个元件） | **schemdraw** | 相对定位链自动顺延；手搓要重算后续坐标 |
| 要导入嘉立创 | KiCad 链 | 与上面都无关 |

两者**依赖相同**（matplotlib），不增加环境负担：

```bash
pip install schemdraw      # 清华源直连，约 5 秒，无编译无 UAC
```

**最小用法**：

```python
import schemdraw
import schemdraw.elements as elm
with schemdraw.Drawing(file='out.png') as d:
    d += elm.SourceV().up().label('5V')
    d += elm.Resistor().down().label('R1\n10k')
    d += elm.Dot()
    d += elm.Line().right()
    d += elm.Resistor().down().label('R2\n10k')
    d += elm.Ground()
```

### ⚠️ schemdraw 的失效模式是静默的

**实测**：用 `elm.Ic(pins=[...])` 拼一个 AD7606 风格的芯片，`AVCC` 与 `BUSY` 叠字、
`CONVST` 与 `AGND` 叠字、框内引脚名与框外网络名撞在一起 ——
**不报错、不警告、不避让，出来就是废图。**

→ 用它的时候**出图后必须人眼看一遍**，尤其多引脚器件。
→ 这也正是多引脚 IC 仍推荐手搓 DSL 的原因：标注位置是你自己摆的，可控。

### 其他已记录的坑（0.23 实测）

1. **无方向元素（`Rect`/自定义形状）会继承画布当前的 `theta`**：前面画过向下的 `Ground`/`LED`，后面 `Rect` 会被带着转 90° → **一律 `.theta(0)` 锁定**。这是"文本在框外/框歪了"类怪相的根因
2. `elm.Rect` **没有锚点**，参数是 `corner1`/`corner2`（元素内相对坐标），不是 `w`/`h`；`.at()` 放的是 `corner1`
3. `elm.Ground()` 符号从锚点**向下延伸约 0.7 单位** —— 下方有横线经过时至少留 0.25 间隙，否则视觉上像短路
4. `elm.Label()` 无内部文本偏移，`.at()` 即文本锚点（配 `halign`）

## 交付模式

**主交付**：工程 zip + PNG 参考图（按模块分张）+ BOM CSV + README

| 交付物 | 要点 |
|---|---|
| 工程 zip | 整个 zip 直接导入，**不要解压** |
| 参考图 | **按模块分张渲染**（通道/通道/电源）。单张大图必然标签打架 |
| BOM CSV | **`utf-8-sig`** 防 Excel 中文乱码；**备注字段含逗号必须加引号**，否则 Excel 列错位 |
| README | 见下 |

**README 必写四项：**

1. **导入步骤**（文件 → 导入 → KiCad → 选 zip）
2. **导入后三项检查**：设计管理器无"未连接" / 每个元件封装非空 / **点一次"转换到 PCB"**（免费的体检，不画 PCB 也点）
3. **假设声明**：备用件怎么处理、插座类封装、网络名↔丝印映射、电位器接法、二极管方向
4. **重新生成的完整命令**（**写解释器绝对路径**，别写裸 `python`）
